PHP FUNDAMENTALS – NOTES (UP TO MIXED ARRAYS)
Date: 01/08/2026
----------------------------------------------------------------

1. WHAT PHP IS
- Server-side scripting language.
- PHP code runs on the server; the browser receives only output.
- Loosely typed: data types assigned automatically.
----------------------------------------------------------------

2. RUNNING PHP

2.1 CLI (Command Line Interface)
- Used mainly for learning and scripting.
- Command: php filename.php
- Recommended for learning.
- New line character: \n
- HTML tags (e.g., <br>) are printed as plain text.
- Output shown in the terminal.
----------------------------------------------------------------

2.2 Browser (Server Execution)
- PHP runs through a web server (e.g., Apache or PHP built-in server).
- Output rendered as HTML.
- Line break in browser: <br>
- Browser ignores \n.
----------------------------------------------------------------

3. BASIC PHP SYNTAX
- PHP code starts with <?php (closing tag ?> optional).
- Every PHP statement ends with a semicolon (;).
----------------------------------------------------------------

4. VARIABLES
- Start with $.
- Case-sensitive.
- Must start with a letter or underscore (_).
Examples:
- $name = "Pranav";
- $age = 22;
- $isDeveloper = true;
----------------------------------------------------------------

5. DATA TYPES
- Common types: string, integer, float, boolean, array.
Examples:
- $name = "Dexter"; // string
- $age = 22; // integer
- $height = 5.9; // float
- $isActive = true; // boolean
----------------------------------------------------------------

6. DEBUGGING VARIABLES

6.1 var_dump()
- Inspect variables in detail.
- Shows type and value.
- Intended for debugging.

6.2 print_r()
- Cleaner output for arrays.
- Less detailed than var_dump().
- Intended for debugging only.
----------------------------------------------------------------

7. OUTPUT METHODS

7.1 echo
- Outputs text. No return value.
- Example: echo "Hello";

7.2 print
- Outputs text. Returns 1.
- Example: print "Hello";
----------------------------------------------------------------

8. STRINGS
- Double quotes (""): variables interpolated, escapes work.
  Example: echo "Hello $name\n";
- Single quotes (''): variables literal, escapes limited (\\ and \').
  Example: echo 'Hello $name\n';
----------------------------------------------------------------

9. STRING CONCATENATION
- Use dot operator (.).
- Example: echo "Hello " . $name;
----------------------------------------------------------------

10. CLI VS BROWSER OUTPUT
- CLI: newline is \n.
- Browser: line break is <br>.
----------------------------------------------------------------

11. CONDITIONS

11.1 if / else
- Example:
  if ($age >= 18) {
    echo "Adult";
  } else {
    echo "Minor";
  }

11.2 elseif
- Example:
  if ($marks >= 90) {
    echo "Grade A";
  } elseif ($marks >= 60) {
    echo "Grade B";
  } else {
    echo "Fail";
  }
----------------------------------------------------------------

12. COMPARISON OPERATORS
- == equal
- != not equal
- > greater than
- < less than
- >= greater than or equal
- <= less than or equal
----------------------------------------------------------------

13. LOGICAL OPERATORS
- && AND
- || OR
- ! NOT
- Example:
  if ($age >= 18 && $isDeveloper) {
    echo "Adult developer";
  }
----------------------------------------------------------------

14. ARRAYS

14.1 Indexed arrays
- Example: $fruits = ["Apple", "Banana", "Orange"];
- Index starts at 0.

14.2 Associative arrays
- Example:
  $user = [
    "name" => "Dexter",
    "age" => 22
  ];
- Access: echo $user["name"];

14.3 Mixed / nested arrays
- Example:
  $profile = [
    "user" => ["name" => "Dexter", "age" => 22],
    "skills" => ["PHP", "Laravel", "Git"],
    "isActive" => true
  ];
- Access:
  echo $profile["user"]["name"];
  echo $profile["skills"][1];
----------------------------------------------------------------

15. DEBUGGING ARRAYS
- print_r($profile) — readable.
- var_dump($profile) — detailed.
----------------------------------------------------------------

16. GIT LEARNING WORKFLOW
- One concept = one commit.
- Commit messages should describe what was learned.
- Example: "Understand PHP strings and concatenation"
----------------------------------------------------------------

(Notes added 01/08/2026 — continued topics)

WHAT IS DYNAMIC INPUT
- Input that is not hardcoded; comes from outside the PHP file.
- Examples: command line args, user typing at terminal, URL parameters, HTML form input.
- Dynamic input is untrusted.

WHAT ARE SUPERGLOBALS
- Predefined arrays available anywhere in the script.
- Common superglobals:
  - $argv → command line input
  - $argc → number of CLI arguments
  - $_GET → URL parameters
  - $_POST → form data
  - $_SERVER → request and environment info
----------------------------------------------------------------

CLI INPUT USING $argv
- php file.php 5 → $argv[0] = "file.php", $argv[1] = "5"
- $argv exists ONLY in CLI.
- All values are strings.
- Real input starts from $argv[1].
- Example: $limit = (int) $argv[1];
- Validate: if (!isset($argv[1]) || !is_numeric($argv[1])) { exit; }
----------------------------------------------------------------

RUNTIME INPUT USING STDIN
- fgets(STDIN) reads one line; trim() removes newline.
- Example: $name = trim(fgets(STDIN));
- Used only in CLI.
----------------------------------------------------------------

BROWSER INPUT USING $_GET
- URL: file.php?name=Pranav&age=21 → $_GET["name"] = "Pranav"
- Safe access: $name = $_GET["name"] ?? "Guest";
- All $_GET values are strings.
----------------------------------------------------------------

BROWSER INPUT USING $_POST
- $_POST receives form data sent via POST.
- Safe access: $username = $_POST["username"] ?? "";
- Check request method before using.
----------------------------------------------------------------

$_SERVER AND REQUEST_METHOD
- $_SERVER contains metadata.
- Important key: $_SERVER["REQUEST_METHOD"] ("GET" or "POST").
- Example:
  if ($_SERVER["REQUEST_METHOD"] === "POST") {
    // handle form data
  }
----------------------------------------------------------------

PHP_SAPI (EXECUTION ENVIRONMENT)
- Tells how PHP is running:
  - "cli" → terminal
  - "cli-server" → PHP built-in server
  - "apache" → web server
- Example:
  if (PHP_SAPI === "cli") {
    // CLI-only code
  }
----------------------------------------------------------------

WHY INPUT VALIDATION IS REQUIRED
- Input can be missing, empty, wrong type, or malicious.
- Validation ensures:
  - Input exists
  - Input is usable
  - Program does not continue with bad data
- Fail early using exit.
----------------------------------------------------------------

isset() VS empty()
- isset(): checks if variable exists (false if missing or null).
- empty(): checks if value is meaningful (true for "", 0, "0", null, false, []).
- Combined usage:
  if (!isset($var) || empty($var)) { exit; }
----------------------------------------------------------------

TYPE VALIDATION
- Dynamic input arrives as STRING.
- Use is_numeric(), strlen(), (int) $value to validate types.
----------------------------------------------------------------

WHAT IS XSS (CROSS-SITE SCRIPTING)
- Occurs when user input contains HTML/JS and PHP outputs it directly.
- Browser executes injected code.
- Example attack: <script>alert("Hacked")</script>
----------------------------------------------------------------

XSS PROTECTION: htmlspecialchars()
- Use when displaying untrusted input:
  echo htmlspecialchars($username, ENT_QUOTES, "UTF-8");
- Converts < > " ' into safe text.
- Seeing script tags printed as text means protection worked.
----------------------------------------------------------------

IMPORTANT SECURITY RULE
- Do NOT sanitize input when storing.
- Escape only when displaying output.
- Flow: Input → Validate → Use → Escape on output.
----------------------------------------------------------------

SECURITY MENTAL MODEL
- Receive input
- Check existence
- Check validity
- Use safely
- Escape before output
----------------------------------------------------------------
